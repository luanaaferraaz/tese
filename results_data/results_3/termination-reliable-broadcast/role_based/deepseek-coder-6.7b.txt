Termination: This property is satisfied as the protocol ensures that every correct process eventually delivers a message, which means it will not get stuck in an infinite loop waiting for a message.

Validity: This property holds true if and only if sender s broadcasts m and at least one other correct process delivers m. If this property does not hold, then there must be some faulty process that is processing the same round but not delivering any messages. However, since the protocol ensures every correct process eventually delivers a message, it would imply that the algorithm may have crashed in the past rounds which has caused non-delivery of m by at least one other process.

Agreement: This property implies that if a correct process delivers m, then all correct processes eventually deliver m. If this property does not hold, there must be some faulty or faultless process that is processing the same round but not delivering any messages for the current round or in past rounds respectively. However, since the protocol ensures every correct process eventually delivers a message, it would imply that at least one other correct process has crashed and caused non-delivery of m by this process which violates the agreement property.

Integrity: This property ensures that every correct process delivers at most one message. If there are more than one messages delivered by a single process in a round, then it contradicts with our protocol design as per invariant I1 and I2 where each correct process must have received only one message in the end of round f+1 or SF token.

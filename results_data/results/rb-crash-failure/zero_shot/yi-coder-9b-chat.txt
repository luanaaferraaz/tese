- RB-Validity - [satisfied]
- RB-Agreement - [satisfied]
- RB-Integrity - [non satisfied]: The algorithm does not strictly enforce the RB-Integrity property. While it keeps track of delivered messages and prevents a duplicate delivery, there is no mechanism to ensure that a correct process delivers m only if m was broadcasted once by the broadcaster. The correctness argument assumes that if a process receives m, then it forwarded <type1, m> to its neighbours. However, this does not guarantee that the process did so for the first and only time because of the message received from the broadcaster (type0).

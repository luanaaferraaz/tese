Cachin, C., Guerraoui, R. and Rodrigues, L. (2011). Introduction to Reliable and Secure Distributed Programming, Springer.
ALGORITHM: Best-Effort Broadcast
1) IDENTIFICATION

    Algorithm name: Best-Effort Broadcast

    Problem type: Broadcast

    Variant tags:

        Fault model: [C] Crash

        Timing model: [AS] Async

2) SYSTEM MODEL

    Processes: n

    Max faulty: Not explicitly bounded

    Resilience condition: Relies on the existence of Perfect Point-to-Point Links

    Channels / communication assumptions: Perfect Point-to-Point Links (No creation, no alteration, no duplication, no loss)

    Timing assumptions: None (asynchronous)

    Additional assumptions: Messages are unique; no process broadcasts the same message twice; no two processes broadcast the same message

3) CORRECTNESS PROPERTIES

    Validity: If a correct process broadcasts a message m, then every correct process eventually delivers m.

    No duplication: No message is delivered more than once.

    No creation: If a process delivers a message m with sender s, then m was previously broadcast by process s.

4) INTERFACE (API)

    External operations: ⟨beb,Broadcast∣m⟩

    Output events: ⟨beb,Deliver∣p,m⟩

5) ROLES

    Broadcaster: process that invokes beb.Broadcast

    Receiver: processes that trigger beb.Deliver

6) LOCAL STATE (per process)

Constants:

    n: The set of all processes.

Variables:

    (None specified in the algorithm's local state; it is a stateless transformation of events).

7) MESSAGE TYPES

    m: The unique message content broadcast to all processes.

Validation rules:

    message uniqueness is assumed

    delivery events must correspond to previously broadcast messages

8) INITIALIZATION

    None specified by the abstraction.

9) PROTOCOL PSEUDOCODE

A) On external invocation:

    upon event ⟨beb,Broadcast∣m⟩ do:

        forall q∈n do:

            trigger ⟨pl,Send∣q,m⟩

B) On message receive:

    upon event ⟨pl,Deliver∣p,m⟩ do:

        trigger ⟨beb,Deliver∣p,m⟩

10) DECISION / DELIVERY RULE

    Deliver m when:

        the module triggers event
        ⟨beb, Deliver | p, m⟩

    After delivery:

        the message is passed to the upper layer of the system

11) QUORUM

    (Not applicable; this is a broadcast primitive).

12) INVARIANTS

    I1: m delivered ⟹m was broadcast by s (Integrity).

    I2: m is delivered to process p at most once (No duplication).

13) CORRECTNESS ARGUMENT SKELETON

Safety:

    No creation: Derived directly from the "no creation" property of the underlying perfect links.

    No duplication: Relies on the perfect links "no duplication" property and the uniqueness of messages.

    Validity: Derived from the reliable delivery property of perfect links; if the sender is correct, it sends the message to all q∈n, and perfect links ensure they all deliver it.
